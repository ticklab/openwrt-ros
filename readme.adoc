== ROS 2 distribution source builds

Each distribution directory (`ros2-humble`, `ros2-jazzy`, `ros2-lyrical`) provides a
source-build package for the corresponding ROS 2 distribution, following the
official Ubuntu-Development-Setup flow: the workspace is fetched with
`vcs import` from `ros2.repos`, then cross-compiled with `colcon` against the
OpenWrt toolchain and installed under `/opt/ros/<distro>` on the target rootfs.

[cols="1,2,3"]
|===
| Package | Distribution | Description

| ros2-humble | Humble Hawksbill | Source build from the ros2/ros2 humble branch
| ros2-jazzy | Jazzy Jalisco | Source build from the ros2/ros2 jazzy branch
| ros2-lyrical | Lyrical | Source build from the ros2/ros2 lyrical branch
|===

Each distribution is split into a core runtime package and a separate demo
package:

[cols="1,2,3"]
|===
| Core package | Demo package | Description

| ros2-humble | ros2-humble-demo | Demo/tutorial nodes from ros2/demos
| ros2-jazzy | ros2-jazzy-demo | Demo/tutorial nodes from ros2/demos
| ros2-lyrical | ros2-lyrical-demo | Demo/tutorial nodes from ros2/demos
|===

Notes:

* Sources are pinned to a specific commit of the corresponding branch and
  `PKG_MIRROR_HASH` is generated by the OpenWrt download flow.
* `Build/Prepare` keeps the fetched workspace outside `PKG_BUILD_DIR` and
  runs `vcs import --retry 5 --skip-existing`, so transient network failures
  do not corrupt the workspace.
* `Build/Configure` generates a CMake cross-compilation toolchain file from
  `files/openwrt-toolchain.cmake.in`.
* `Build/Compile` invokes `colcon build --executor sequential --merge-install`
  with the toolchain file; sequential execution guarantees that dependency
  packages finish installing before their dependents are built.
* The resulting core `.ipk` installs only the runtime part under
  `/opt/ros/<distro>` (no headers, sources or CMake package files) together
  with a `files/setup.sh` that sets up the environment for the target path
  `/opt/ros/<distro>`.
* Both packages are produced from the same colcon build. The payload of the
  demo packages listed in `ros2/demos` is taken from the colcon install
  manifests and moved into the separate `<distro>-demo` `.ipk`, so the core
  runtime can be installed without the demo/tutorial nodes. The demo package
  depends on the core package.

=== DDS middleware selection

Each distribution builds both the Fast DDS (`rmw_fastrtps_cpp`) and Cyclone
DDS (`rmw_cyclonedds_cpp`) middleware implementations. A menuconfig choice
("DDS middleware" -> "Default DDS middleware") selects which one is used as
the default via the `RMW_IMPLEMENTATION` CMake option. The default is
Fast DDS. The choice only sets the default; it can still be overridden at
runtime with the `RMW_IMPLEMENTATION` environment variable.

== System libraries

The `libs/` directory provides third-party C/C++ libraries that are either
missing from the default OpenWrt feeds or need a specific version for the
ROS 2 distributions.

[cols="1,1,3"]
|===
| Package | Version | Description

| asio | 1.22.1 | Header-only C++ networking library (Fast DDS). Pinned to
  keep the deprecated `asio::io_service` API required by Humble's Fast DDS 2.6.x
| console_bridge | 1.0.2 | Simple C++ logging abstraction required by
  `console_bridge_vendor` / rosconsole_bridge
| cpptoml | 0.1.1 | Header-only TOML parser required by iceoryx
| eigen | 3.4.0 | Header-only C++ linear algebra library
| foonathan-memory | 0.7.4 | Custom memory allocator used by Fast DDS
  (`foonathan_memory_vendor`)
| orocos-kdl | 1.5.1 | Orocos Kinematics and Dynamics Library
| pybind11 | 2.11.1 | Seamless C++/Python interoperability
| spdlog | 1.12.0 | Fast C++ logging library
| tinyxml2 | 10.0.0 | Small C++ XML parser
| yaml-cpp | 0.8.0 | YAML parser/emitter required by `yaml_cpp_vendor`
  (>= 0.8.0)
|===

Upstream `*_vendor` ROS packages download their third-party dependencies from
the network at build time. Providing these libraries as OpenWrt packages makes
the ROS 2 build hermetic and reproducible: the vendor packages detect the
system installation and skip the download step.

| python3-notify2 | 0.3.1 | Python interface to DBus notifications

empy is provided as two versioned packages because Humble's
`rosidl_adapter` requires the empy 3.x API (`em.BUFFERED_OPT` /
`em.RAW_OPT`) while Jazzy/Lyrical use the 4.x API.

NOTE: colcon/ROS upstream lists testing tools such as pytest as
install_requires; following OpenWrt packaging conventions, only runtime
dependencies are kept here and test dependencies are omitted.

=== Host-only helper packages

Some Python modules are only needed in the host Python environment during
the build (code generation or build backends), not on the target. These are
packaged host-only (installed into `staging_dir/hostpkg`).

|===
| Package | Version | Description

| python3-argcomplete-host | 3.2.1 | Needed by the colcon-argcomplete extension at CLI startup

| python3-meson-host | 1.5.1 | Importable mesonbuild module for the meson-python backend
| python3-meson-python-host | 0.18.0 | PEP 517 backend used to build host numpy
| python3-numpy-host | 2.2.1 | Needed by rosidl_generator_py for message generation
| python3-pyparsing-host | 3.1.1 | Imported by catkin_pkg during ament_cmake/colcon runs
